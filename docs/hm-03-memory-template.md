# HM-03 · 人设分区记忆维护模板（收尾指令）

> **任务编号**：HM-03（Hermes 执行者承接）
> **依据**：Hermes 记忆系统机制（HM-MEMORY-QUERY 实测）+ AGENTS.md §4 记忆写入规范
> **核心模式**：常驻小文件全量注入 + 大容量按需检索 + 预算硬顶逼压缩 + 三层记忆边界
> 更新日期：2026-08-09 · 版本 v1.0

---

## 1. 三层记忆边界（谁记什么）

| 层 | 位置 | 内容 | 生命周期 |
|----|------|------|----------|
| **内层** 单角色视角 | `personas/<id>/memory.md` | 该人设视角下的老板偏好/约定/重要事件（类比：该角色的 USER.md + 事件日志） | 随角色存在，滚动压缩 |
| **中层** 全局事实 | cyber-girlfriend profile 的 `MEMORY.md` | 跨人设的老板偏好/项目规则/长期约定 | 长期 |
| **外层** 主 profile | 主 profile 的 MEMORY.md / mem0 | 与赛博女友完全隔离（红线 10） | 永不触碰 |

**写入优先级**：能落单角色 → 单角色；跨人设才上浮到专用 profile MEMORY.md；主 profile 永不写。

---

## 2. 收尾指令模板（赛博女友后端拼入每条指令末尾）

> **用途**：每次 Hermes 执行完任务后，统一评估一次"是否有值得记住的新事实"，有则写入，无则跳过。事件驱动，非定时。

```text
【记忆维护（收尾指令，必读必执行）】
1. 若本次对话/任务中出现【值得该人设记住的新事实】（老板偏好、约定、决策、重要事件），
   用文件工具【绝对路径】追加到 personas/<id>/memory.md 的「近期对话」区：
   格式：- [YYYY-MM-DD] 内容（一行一条）
2. 若「近期对话」超过 20 条 或 memory.md 超过 3KB，触发压缩：
   读全文 → 合并去重 → 改写为「长期记忆」摘要（旧条目归档），防膨胀
3. 跨人设的全局事实（老板偏好/项目规则/长期约定）→ 写 cyber-girlfriend profile 的 MEMORY.md
4. 不要写入【任何其他记忆系统】（主 profile MEMORY.md / mem0 永不触碰）
5. 写文件用"读-合并-写"模式（先读当前内容，追加/改写，不整文件覆盖），防并发冲突
```

---

## 3. memory.md 文件格式（内层）

```markdown
# 小呆的记忆区（角色视角）

## 长期记忆（压缩摘要）
- 老板喜欢喝美式咖啡
- 上周陪老板讨论了 NAS 分流方案
- 老板拍板：人设记忆持久分区，新对话时切换

## 近期对话（滚动）
- [2026-08-09] 老板说想搭建 S2S 对话窗口
- [2026-08-09] 老板确认 Hermes 负责记忆维护（HM-03）
- [2026-08-09] 老板喜欢用 kanban 派活，不喜欢阻塞等待
```

**写入纪律**（对齐 Hermes 机制）：
- 写**陈述性事实**（"老板喜欢 X"✓），不写指令性句子（"帮老板做 X"✗）
- 一条一个事实，紧凑高信号
- 对话细节/临时状态**不落盘**（随会话结束消失）

---

## 4. 压缩规则（预算硬顶，不靠 LLM 自觉）

| 触发条件 | 动作 |
|----------|------|
| 「近期对话」> **20 条** | 读全文 → 合并去重 → 改写成「长期记忆」摘要 |
| memory.md > **3KB** | 同上（阈值写死在模板，参数化版本） |
| 压缩后 | 旧条目归档/删除，保留高信号事实 |

---

## 5. 更新时机

- **事件驱动，非定时**：每轮对话收尾指令统一评估一次（"若出现值得记住的新事实则追加"）
- 切换人设：只写 `active.txt` 一行 id，**不迁移、不触发记忆写入**
- 长对话多轮：每轮结束检查，不是定时任务
