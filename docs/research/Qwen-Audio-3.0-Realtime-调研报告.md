## 3. 核心能力详解

### 3.1 毫秒级响应，又快又聪明

- 官方时延压到 **120ms 以内**（Qwen3-Omni 为 211ms，人类反应 ~250ms）
- 不因低延迟牺牲智商：VoiceBench 上 Plus 版标准/口语化提问 92.5/90.5，**口语化只掉 2.0 分**——扛得住真人说话的随意性
- Preview 版曾在 Artificial Analysis 上语音推理 97.6%、对话流畅度 97.8% 双双登顶（超过 GPT-Realtime-2 High）

### 3.2 全双工对话（对讲机 → 真人对话）

内置"多模态感知双工控制子模型"：
- **边说边听**：用户可以随时打断、插话
- **抗噪声**：嘈杂环境不误触发，精准锁定你的声音
- **多人场景**：识别主对话对象，不被旁听者干扰
- **多说话人切换**：按上下文与语义线索自然过渡
- **声纹聚焦**：API 预留 `audio_prompt` 字段，上传音频样本可锁定特定说话人

### 3.3 情感化语音（赛博女友的灵魂）

- 动态调整语气、节奏、音调、情感（"用疲惫但温柔的语气说晚安" → 主动压低声线、放缓尾音、加呼吸感）
- 能模拟笑声、叹息、犹豫等**副语言信号**
- 角色扮演时按设定切换说话风格与用词（历史人物/职业身份）
- **音色克隆**：支持自定义音色微调；预置 Vivian（邻家女声）/ Emma（职场女声）/ Ryan（阳光男声）/ Jack（成熟大叔）

### 3.4 角色设定直接支持（关键！）

- Realtime API 通过 **`instructions` 系统消息字段**设定角色
- 官方示例："你是某五星级酒店的 AI 客服专员，请准确且友好地解答客户关于房型、设施、价格、预订政策的咨询"
- 上下文管理：`conversation.item.create` 事件可插入 **system / user / assistant** 对话项（注入历史、系统指令、历史工具调用记录），支持任意位置插入
- 输出模态：`modalities` 支持 `["text"]` 或 `["text","audio"]` —— **语音 + 文字双输出** ✅

### 3.5 Agent 原生工具调用

- FunctionCall 标准协议，支持 **MCP / API / 知识库** 接入
- 调用结果自动融入对话记忆，后续追问可衔接上一次结果
- 为后续"女友帮干活"（Hermes / 工具调用）预留天然通道

### 3.6 技术底子（为什么强）

- **On-Policy Distillation**：把文本大模型的完整推理能力蒸馏进语音模型，生成时实时纠正
- **多教师蒸馏**：口语多轮教师（口语化表达）、通用教师（问答推理）、Agentic 教师（工具调用）、音频理解教师（副语言/音频语义）——四条主线不偏科

## 6. 选型建议

**✅ 主选 Qwen-Audio-3.0-Realtime-Flash**，理由：

1. **需求匹配**：项目要的是"语音进 → 语音+文字出、实时、可打断"——这正是它的看家本领；Qwen3-Omni 的图像/视频能力我们用不上
2. **延迟更低**：<120ms vs 211ms，双工交互（像真人聊天，不像对讲机）
3. **情感陪伴体验**：项目叫"赛博女友"，情感表达、音色克隆、风格切换正是核心体验，官方场景直接列了"情感陪伴"
4. **角色注入无坑**：instructions 字段官方示例就是设定角色，无 Qwen-Omni-Turbo 的"不支持 system message"问题
5. **Agent 能力预留**：原生 FunctionCall + MCP，与项目后续"女友帮干活"规划天然衔接
6. **成本可接受**：Flash ¥3/¥30 每百万 token，个人聊天量级很便宜

**权衡说明**：Qwen3-Omni 开源可本地部署（隐私/离线场景），保留为备选；若未来需要本地化可无缝切换。
