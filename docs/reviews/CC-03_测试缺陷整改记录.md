### 1.2 DEF-A-02：ws-smoke personasDir 路径校验拦截（M-A-TC-014/015/016）
- **原因分析**：**根因非"测试环境配置"**——`config/apikeys.json` 中 `hermes.personasDir` 为正斜杠格式（`C:/Users/.../personas`），FilePersonaProvider 内 `resolve(personasDir, id)` 在 Windows 输出反斜杠，H6 校验 `dir.startsWith(this.personasDir)` 因分隔符不一致恒为 false → 误判"非法人设 id:xiaodai(路径越界)"。**该缺陷同样影响生产装配（index.ts 用同一 config 值），属真实代码缺陷**（H6 校验未规范化 base 路径），单模块报告登记为"测试环境配置"为误判
- **整改内容**：测试侧修复——ws-smoke-test.ts 的 resolveInstructions 中先用 `resolve(config.hermes.personasDir)` 规范化目录再传给 provider（同格式路径下 startsWith 成立）；代码注释注明根因。**治本修复（H6 校验改为 `startsWith(resolve(this.personasDir))`）属业务代码改动，按红线已上报老板，未擅自修改**
- **处理过程**：修改 `app/server/ws-smoke-test.ts`（import resolve + 规范化 personasDir）；先单测验证 FilePersonaProvider 链路（resolve 后 listPersonas 3 角色、getPersona 正常），再跑真实 ws-smoke
- **验证结果**：✅ ws-smoke-test 6/6 通过（①②③④⑤⑥，真实 Qwen 会话建立 + 人设注入 session.updated 成功）
- **状态**：✅ 已验证关闭（测试侧）；⚠️ 遗留真实代码缺陷已上报（H6 校验规范化）

### 1.3 DEF-V-01：gateway 二进制音频帧不直通（M-V-TC-042）
- **原因分析**：前端通过 base64 JSON 发送音频（`{type:'audio', data:base64}`），gateway 仅处理 text 帧；"二进制帧直通"测试的是架构不需要的场景（设计边界）
- **整改内容**：按说明文档方案 A——删除该用例，并在文件头注释 + 用例位置双处注明"二进制帧直通为设计边界（前端走 base64 JSON），删除而非标注失败，防后续误以为遗漏；未来如需支持，gateway 增加 Buffer 识别分支后恢复用例"
- **处理过程**：修改 `voice-shell/gateway-unit-test.ts`（删除 M-V-TC-042 用例及 pcm16k2 变量、更新头注释验收项、删除处加说明）
- **验证结果**：✅ gateway-unit-test 25/25 通过（原 26 用例删 1）
- **状态**：✅ 已验证关闭

## 4. 最终结论与遗留事项

**整改结论**：3 个缺陷（DEF-A-01/02/V-01）全部整改并验证关闭；M-P/M-C 补测完成（各 9 用例全过，BLOCKED 清零）；全量回归后端 12 文件 + 前端 6 脚本全部 PASS，根/client tsc 零错误，前端 build 通过。CC-03 整改目标全部达成。

**遗留事项**：
1. ⚠️ **真实代码缺陷（已上报，待老板拍板）**：`persona/file-persona-provider.ts` H6 路径校验 `dir.startsWith(this.personasDir)` 未规范化 base 路径——Windows 下 config 的正斜杠 personasDir 经 resolve 后变反斜杠，校验恒 false，误报"路径越界"；**生产装配（index.ts）同样受影响**。本次仅在测试侧以 resolve 规范化规避（ws-smoke/M-P 测试均通过）；建议后续将校验改为 `dir.startsWith(resolve(this.personasDir))`（或统一 path.normalize 后比较）作为独立修复，需老板确认后执行
2. M-C 测试"文件缺失 → env 兜底"分支因 loader 无注入点无法端到端覆盖（已在 §2.2 注明），如后续 loader 支持注入 CONFIG_PATH 可补强
3. DEF-V-01 删除的二进制帧用例：若未来前端改走二进制帧直通，需在 gateway 增加 Buffer 识别分支并恢复 M-V-TC-042
