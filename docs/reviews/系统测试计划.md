## 1. 测试概述

### 1.1 目的
在单模块测试（L1/L2）全部通过的基础上，对**系统整体**执行端到端测试（L3 真实链路），验证：

1. **全链路连通**：浏览器 → 后端 REST/WS → Qwen-Audio（语音壳）→ Hermes（大脑）→ 回传前端
2. **核心场景达标**：快问快答 / 复杂事务 / 人设切换 / 数字人联动 / 语音会话
3. **降级链路可靠**：Hermes 不可用 → 纯 Qwen 兜底（M5-02）
4. **系统健壮性**：错误处理、并发、断连恢复

### 1.2 系统架构与测试链路

```
[浏览器 client:5173] ──REST /api/*──▶ [后端 app:3000]
        │                                  │
        └──WS /ws/voice──▶ [voice-shell] ──▶ Qwen-Audio（语音壳）
                                            │ function_call
                                            ▼
                                    [brain: hermes-runner / qwen-fallback]
                                            │
                                    [Hermes 大脑（本机）/ 降级纯 Qwen]
```

**测试边界**：从**前端入口**（HTTP 请求 / WS 连接）到**系统响应**（REST 响应 / WS 下行事件 / 前端渲染），覆盖整条链路。不测单模块内部（已由单模块测试覆盖）。

### 1.3 系统测试场景清单

| 场景号 | 场景 | 链路 | 级别 |
|--------|------|------|------|
| SYS-01 | 系统健康检查 | 后端 /api/health + 前端页面 | 正常 |
| SYS-02 | 文字聊天-快问快答 | 前端 → /api/chat → Qwen 直答 | 正常 |
| SYS-03 | 文字聊天-复杂事务 | 前端 → /api/chat → Hermes 执行 | 正常 |
| SYS-04 | 人设切换 | /api/personas 列表 + 切换 + 生效 | 正常 |
| SYS-05 | 语音会话全链路 | WS /ws/voice → Qwen → 音频/字幕/情绪 | 正常 |
| SYS-06 | Function Calling 中转 | 语音/文字 → function_call → Hermes → 写回 | 正常 |
| SYS-07 | 数字人联动 | 情绪事件 → 素材选片 → 前端播放 | 正常 |
| SYS-08 | Hermes 降级 | Hermes 不可用 → 纯 Qwen 兜底 | 异常 |
| SYS-09 | 参数非法 | 错误 JSON / 缺字段 / 错 method | 异常 |
| SYS-10 | 断连与恢复 | WS 断开 → 重连 → 恢复对话 | 边界 |
| SYS-11 | 并发请求 | 多请求并发 → 无崩溃无串扰 | 边界 |
| SYS-12 | 性能基准 | 各场景耗时记录（对照 M5-01 验收） | 性能 |

## 4. 测试用例设计规范

### 4.1 标准用例模板（与单模块测试一致，术语统一）

```
┌─────────────────────────────────────────────────────────────┐
│ 用例 ID:   SYS-<场景号>-TC-<序号>  例: SYS-02-TC-001          │
│ 用例名称:  <一句话描述>           例: 快问快答正常返回          │
│ 用例类型:  [正常路径 / 边界条件 / 异常输入 / 性能]             │

│ 输入:      <请求内容 / 参数>                                 │
```

| SYS-08 降级 | Hermes 不可用→纯 Qwen 回复 | 半途失败 | - |

## 5. 执行步骤（分阶段）

### 阶段 0：环境准备
执行 §2.1 检查 + §2.2 启动系统，确认前后端都健康。

### 阶段 1：静态核查
```bash
# 确认关键接口存在
grep -n "router.post\|router.get" app/server/routes.ts | head -10
grep -n "ws" app/server/index.ts | head -5
```

### 阶段 2：逐场景执行（SYS-01 → SYS-12）
每个场景按用例模板执行，**用 curl / node 脚本驱动真实链路**：

```bash
# 示例：SYS-02 快问快答
curl -s -X POST http://localhost:3000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"你好呀","personaId":"xiaodai"}' | python -m json.tool

# 示例：SYS-04 人设列表
curl -s http://localhost:3000/api/personas | python -m json.tool

# 示例：SYS-05 WS 语音（复用 voice-shell/gateway-smoke-test.ts）
node --experimental-strip-types voice-shell/gateway-smoke-test.ts

# 示例：SYS-06 FC 中转（复用 voice-shell/function-calling-unit-test.ts）
node --experimental-strip-types voice-shell/function-calling-unit-test.ts
```

### 阶段 3：结果记录
- 每条用例：填实际结果 + 判定（PASS/FAIL/BLOCKED）
- FAIL → 立即写入配套整改文档（§2 缺陷清单，缺陷 ID 前缀 `DEF-SYS-`）

### 阶段 4：性能记录（SYS-12）
对 SYS-02/03 各测 3 次，记录耗时，对照 M5-01 验收标准：
| 场景 | 目标（M5-01） | 当前基线（2026-08-09 实测） |
|------|--------------|------------------------------|
| 快问快答 | <1s | 20.6~39.4s（Hermes 冷启动瓶颈） |
| 复杂事务 | 1.5~6s | 28.5s |
> ⚠️ 当前性能未达标是**已知问题**（ACP 常驻待验证），性能场景判 BLOCKED 或记录基线即可，不阻塞其他场景。

### 阶段 5：汇总
生成系统测试报告（§6 格式），更新配套文档结论。

## 6. 判定准则与报告规范

### 6.1 判定定义（与单模块测试一致）

| 判定 | 条件 |
|------|------|
| **PASS** | 实际结果与预期一致，无未捕获异常，退出码 0 |
| **FAIL** | 断言失败 / 异常 / 输出不符 / 退出码非 0 |
| **BLOCKED** | 前置不满足（依赖/Key 缺失/已知性能瓶颈），无法达标 |

**系统级结论**：
- **通过**：SYS-01~11 全部 PASS（SYS-12 性能作为记录项，不阻塞）
- **不通过**：存在 ≥1 个 FAIL（进入整改）
- **部分通过**：有 BLOCKED（说明原因）

### 6.2 报告输出格式

```markdown
# 系统测试报告
> 测试日期: YYYY-MM-DD · 执行者: <agent> · 级别: L3 真实链路

## 摘要
| 指标 | 值 |
|------|-----|
| 场景数 | 12 |
| 用例总数 | N |
| PASS / FAIL / BLOCKED | N / N / N |
| 系统结论 | 通过 / 不通过 / 部分通过 |

## 场景结果
| 场景 | 用例数 | 结果 | 备注 |
|------|--------|------|------|
| SYS-01 健康检查 | | PASS | |
| ... | | | |

## 性能记录（SYS-12）
| 场景 | 第1次 | 第2次 | 第3次 | 平均 | 目标 |
|------|-------|-------|-------|------|------|
| 快问快答 | | | | | <1s |
| 复杂事务 | | | | | 1.5-6s |

## 缺陷关联
- 关联 DEF-SYS-* 清单（详见配套文档）
```
