# Hermes 相关功能 · 实现方法文档（给 Hermes Agent 评估用）

> **文档定位**：赛博女友项目中所有涉及 Hermes 的功能需求汇总。
> **读者**：Hermes Agent（本机 v0.20.0）——请自行评估每项**是否可实现**、**是否有更好的实现方法**，给出你的方案。
> **背景信息**：赛博女友 = 纯交互界面（云端 Qwen-Audio 语音壳 + 本机 Hermes 大脑）。赛博女友侧**零持久化、无数据库**，记忆与事务全部归 Hermes 管理。

## 1. 项目背景（简单版）

- **赛博女友**是老板的一个 AI 语音陪伴应用：
  - **云端**：Qwen-Audio-3.0-Realtime-Flash 负责"听和说"（语音壳，实时语音对话）
  - **本机**：Hermes Agent 负责"大脑和手"（复杂事务执行、记忆、工具调用）
  - 两者通过**纯文本**衔接：Qwen 遇到复杂问题 → 文本发给 Hermes → Hermes 干活 → 结果文本回传 → Qwen 说出来
- **红线**：赛博女友不存数据、不建库；记忆/会话状态全在 Hermes 侧；一切持久化归你（Hermes）管理。

## 3. 待评估功能清单（请 Hermes 判断实现方式）

> 以下功能**只描述需求**，不预设实现方法。请逐项评估：**可实现？最优方案是什么？**

### 3.1 人设管理（已有雏形，需确认更优做法）

**需求**：
- 赛博女友需要"多个人设"（如：小呆=元气少女、知心姐姐=温柔、助手=干练）
- 用户（老板）可以随时**切换人设**，切换后说话风格跟着变
- 人设数据（名字、性格、说话风格、instructions）**由 Hermes 维护**，赛博女友不存

**现状**：通过 `hermes -z` 发"列出人设/加载人设/切换人设"指令，解析 JSON。
**请评估**：
- 当前用 `hermes -z` 一次性指令 + JSON 交互是否合理？
- 是否有更可靠的方式管理"人设"这类**结构化数据**（比如你的记忆系统 MEMORY.md、或专门的数据文件）？
- **已知问题**：`switchPersona` 实测超时（>120s）——指令太长导致 Hermes 思考过久。有没有更快的切换方式？

### 3.2 会话记忆（赛博女友侧不存，靠 Hermes 记）

**需求**：
- 老板和赛博女友聊天，**跨会话记得老板**（名字、喜好、聊过什么）
- 但赛博女友是纯交互界面，**不持久化**——记忆全靠 Hermes

**请评估**：
- 你的内置记忆系统（MEMORY.md / USER.md / memories/）如何被 `hermes -z` 一次性任务利用？
- 每个 `hermes -z` 是独立进程，**记忆上下文怎么带**？是把记忆摘要拼进指令？还是有会话模式可用？
- 长期记忆如何沉淀（谁总结、谁写入）？

### 3.3 复杂事务执行（已有雏形，需确认边界）

**需求**：
- 老板说"帮我把这个文件整理一下"→ Qwen 识别为事务 → 发 Hermes → 真实执行（文件操作/查资料/跑命令）
- 需要返回**可朗读的文本结果**（Qwen 念给老板听）

**现状**：`hermes -z "任务"` 一次性执行，stdout 捕获结果。
**请评估**：
- 一次性 `-z` 对"文件操作、查资料"这类任务够用吗？
- 有没有任务需要**多轮交互**（一次搞不定，需要追问）？如果有，怎么处理（比如 `--resume` 会话、`mcp serve` 常驻、还是让 Qwen 追问后重发）？
- 长耗时任务（>2 分钟）怎么处理——超时、异步、还是先回复"在处理中"？

### 3.4 工具调用能力（你 50+ 工具怎么暴露给赛博女友）

**需求**：
- Hermes 有 50+ 内置工具（终端、文件、浏览器、Git 等）
- 赛博女友需要让这些工具**按需被调用**

**请评估**：
- 通过 `hermes -z` 时，工具是**自动可用**的吗？还是需要特殊参数（如 `-t` 指定工具集、`--yolo` 免确认）？
- 有没有需要**限制工具范围**的场景（防止误操作）？如何配置？

### 3.5 常驻模式 vs 一次性（架构选型确认）

**需求**：
- 当前方案：每次事务 `hermes -z` 启动一个进程（冷启动开销）
- 可选项：`hermes mcp serve` / `hermes serve` 常驻

**请评估**：
- 一次性 `-z` 的冷启动延迟实测多少？对"快问快答"体验影响大吗？
- 常驻模式（mcp serve / serve）的接入复杂度 vs 收益，值得上吗？
- 如果上常驻，赛博女友 Node.js 侧怎么对接最干净（stdio JSON-RPC？WebSocket？HTTP？）

### 3.6 身份与多会话（可选增强）

**需求**：
- 可能多个用户/多个会话同时使用，需要**隔离上下文**
- 但赛博女友当前是单用户（老板），这个可以 P2 延后

**请评估**：先不深入，简单说下 `--pass-session-id` / `--resume` 是否天然支持隔离即可。
